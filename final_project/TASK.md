# Ваш финальный проект: от данных к приложению

Мы с вами научились исследовать данные, готовить признаки и строить модели. Теперь предлагаю собрать эти навыки в одном проекте: создать приложение, которое сможет предсказывать цену квартиры и вероятность принадлежности квартиры к классу 1.

У вас уже есть данные и заготовки ноутбуков и приложения. Они помогут сориентироваться, а выбор обработки, эксперименты и само решение будут вашими. Новые идеи приветствуются! Ниже — маршрут, по которому удобно двигаться.

## Как организовать проект

Давайте сохраним понятную структуру: данные — в `data`, ноутбуки — в `notebooks`, обученные модели — в `models`, а приложение и инструкция запуска — в корне проекта. К завершению работы папка будет выглядеть так:

```text
final_project/
├── README.md                    # запуск приложения, ваши результаты и ссылки
├── TASK.md                      # задание проекта
├── app.py                       # ваше готовое Streamlit-приложение
├── requirements.txt             # все необходимые библиотеки
├── .gitignore                   # исключения для Git
├── data/
│   ├── README.md                # описание полей
│   ├── regression.csv           # данные для регрессии
│   └── classification.csv       # данные для классификации
├── notebooks/
│   ├── EDA_ideas.ipynb          # анализ и подготовка данных, ваши наблюдения
│   ├── 01_regression.ipynb      # обучение и проверка регрессии
│   └── 02_classification.ipynb  # обучение и проверка классификатора
└── models/                      # появится после обучения
    ├── price_model.joblib      # модель цены и значения для подготовки входов
    └── class_model.joblib      # классификатор и значения для подготовки входов
```

Если после EDA сохраняете новые версии CSV, положите их тоже в `data` и укажите их имена в ноутбуках обучения. Метрики, графики и объяснения удобно оставить в ноутбуках, а основные результаты кратко описать в README.

Важно, чтобы этапы были связаны: **анализ и подготовка данных → обучение и проверка → сохранение моделей → загрузка моделей в приложении**. Приложение использует готовые файлы из `models` и повторяет ту же подготовку входов, что и ноутбуки; заново обучать модели при запуске приложения не нужно.

При загрузке в отдельный репозиторий GitHub разместите содержимое `final_project` в его корне, сохранив вложенные папки. Проверьте, что модели тоже загружены, а пути к файлам не привязаны к вашему компьютеру. Окружение `.venv` оставьте локально — библиотеки устанавливаются через `requirements.txt`.

## 1. Познакомимся с данными

Начните с [описания полей](data/README.md) (`final_project/data/README.md`). Посмотрите на типы, пропуски, распределения и повторы, а для классификации — ещё и на баланс классов. Попробуйте поэкспериментировать и проверить какие поля помогут модели, а какие могут подсказать ей готовый ответ. Разбиение `split` уже подготовлено для вас — будем использовать его.

Для этой части загляните в `EDA_ideas.ipynb` в папке `final_project/notebooks`. Там собраны простые примеры анализа и подготовки каждого поля: работа с пропусками, категориями, числовыми значениями и создание новых признаков. Места `TODO` помогут найти шаги для вашего кода, а под строками `Ответ:` можно записать наблюдения.

Это помощник: выбирайте полезные вам подсказки, адаптируйте их и пробуйте собственные методы, в том числе те, которых не было на курсе. В конце ноутбука есть пример сохранения подготовленных датасетов через `to_csv()`. Если сохраните свои версии, укажите их имена в ноутбуках обучения и добавьте выбранные поля в список признаков. Сохраните разбиение train/test, а значения для заполнения пропусков и других обучаемых преобразований определяйте только по train.

За примерами можно возвращаться в папки `lesson_2`, `lesson_3` и `lesson_4` репозитория курса: там есть знакомые ноутбуки по анализу данных, регрессии и классификации. Берите подходящие фрагменты и адаптируйте их, понимая, что делает каждый шаг.

## 2. Попробуем предсказывать цену

В `notebooks/01_regression.ipynb` вас ждут подсказки и места для вашего кода. В этой части нужно:

1. Провести EDA — исследовательский анализ данных: посмотреть на пропуски, распределения и связь признаков с ценой. Подсказки и примеры можно найти в `final_project/notebooks/EDA_ideas.ipynb`; выбирайте подходящие или пробуйте свои идеи.
2. Выбрать признаки и подходящую обработку чисел и категорий. Если сохранили подготовленный датасет после EDA, укажите его имя в ноутбуке регрессии.
3. Получить простой ориентир, например прогноз медианой train, и обучить модель. Начать можно с `LinearRegression` или `Ridge`, но вы можете предложить свой вариант.
4. На test сравнить модель с простым ориентиром по MAE, а дополнительно посмотреть RMSE и R².
5. Записать результаты и разобраться в нескольких крупных ошибках на test.
6. Сохранить модель и нужные значения для повторения обработки признаков, затем пройти проверки в конце ноутбука.

## 3. Перейдём к классификации

В `notebooks/02_classification.ipynb` поработаем с готовой меткой `above_reference`, смысл которой мы обсуждали на занятии. Общая цена входит в признаки при обучении и при работе приложения. Здесь вам предстоит:

1. Посмотреть на баланс классов и подготовить признаки, включая общую цену квартиры `price_rub` в рублях. Саму цель и служебные поля во входы не включаем.
2. Сравнить простой ориентир, например `DummyClassifier`, с обучаемой моделью. Можно начать с `LogisticRegression`.
3. Для перехода от вероятности к классу использовать порог 0.5: вероятность не меньше 0.5 даёт класс 1, иначе 0.
4. На test сравнить модель с простым ориентиром по precision, recall, F1 и ROC AUC, построить матрицу ошибок.
5. Сохранить модель, список полей, порог и нужные значения для обработки новых данных, затем пройти проверки.

## 4. Дадим место вашим идеям

Давайте проверим, помогают ли адресные признаки. Для обеих задач сравните одну и ту же модель на трёх наборах: без района и улицы → с районом → с районом и улицей. Остальные настройки оставьте одинаковыми, а качество сравнивайте на test. Обучайте каждый вариант только на train. Это учебное сравнение: если по test вы выбираете лучший вариант, полученная метрика уже не является независимой итоговой оценкой. Просто отметьте это в своих выводах.

Затем попробуйте хотя бы одну дополнительную идею. Например, другую обработку пропусков, объединение редких улиц, масштабирование, новый этажный признак или параметр модели. Можно выбрать что-то своё.

Соберите небольшие таблицы результатов и расскажите, что заметили. Если улучшения не получилось, это нормально: такой эксперимент тоже помогает разобраться в данных. Обязательного минимального значения метрики нет — важнее понять результат и корректно его проверить.

## 5. Соберём приложение

Теперь дадим вашим моделям интерфейс. В `app.py` уже есть заготовка, а пример работы со Streamlit можно найти в отдельном открытом репозитории `streamlit-app`, где размещён код уже развёрнутого приложения.

В готовом приложении пользователь должен иметь возможность:

- выбрать регрессию или классификацию и получить ответ от сохранённой модели без повторного обучения;
- загрузить CSV (для классификации — с общей ценой `price_rub`), посмотреть описание полей и скачать пример входного файла;
- получить понятное сообщение, если файл пустой, не хватает столбцов или указан невозможный этаж;
- получить прогноз даже для незнакомой улицы или пустого района благодаря той же обработке, что использовалась при обучении;
- увидеть цену в рублях либо вероятность класса 1 и класс по сохранённому порогу 0.5;
- скачать таблицу прогнозов.

Если хочется развить приложение, добавьте форму квартиры, Excel или графики — выбирайте то, что интересно вам. Для одинаковой квартиры прогноз в приложении и ноутбуке должен совпадать. Согласовать загрузку моделей помогут README и комментарии в `app.py`.

## 6. Подготовим работу к сдаче

Перед завершением перезапустите ядра и выполните ноутбуки сверху вниз. Затем проверьте, что модели загружаются и оба режима приложения работают. Ассерты помогут заметить основные технические ошибки; интерфейс и смысл результатов лучше проверить самостоятельно на нескольких примерах.

В вашей папке или репозитории должны быть:

- выполненные ноутбуки с кодом, метриками, экспериментами и вашими наблюдениями;
- данные, обе обученные модели и сохранённые значения для обработки признаков;
- дописанный `app.py`, зависимости и README с запуском и описанием входов;
- краткое объяснение того, где модели могут ошибаться, и примеры корректного и ошибочного ввода.

Если у вас уже есть собственные обученные модели, их тоже можно использовать. Вместо заполнения шаблонов приложите свои ноутбуки или материалы обучения: расскажите о данных, целях, признаках, экспериментах и качестве. Обе задачи и приложение остаются частью проекта.

Я также посмотрю, как ваши модели работают на отдельном наборе данных. Для этого запишите шаги подготовки признаков и сохраните используемые значения, например медианы и порядок закодированных столбцов. Повторяйте эти шаги для новых квартир без доступа к правильным ответам. В этом проекте достаточно двух частей: train для обучения и test для проверки. Не используйте test для расчёта медиан, обучения кодирования или масштабирования.

Когда всё будет готово, разместите решение в открытом (Public) репозитории GitHub и подключите его на Streamlit Community Cloud. В [README](README.md) (`final_project/README.md`) есть команды, видео и шаги публикации. Для сдачи приложите ссылки на репозиторий и работающее приложение — так вашу работу можно будет открыть и попробовать.

## 7. Как будет оцениваться проект

За проект можно получить **до 10 баллов**:

| Часть работы | Баллы | Что важно показать |
|---|---:|---|
| Анализ и подготовка данных | 2 | Исследованы данные, объяснена обработка полей, сохранено разбиение train/test |
| Регрессия | 2 | Модель обучена, сравнена с простым ориентиром, посчитаны метрики и разобраны ошибки |
| Классификация | 2 | Модель обучена, получены вероятности и классы, посчитаны метрики и объяснена матрица ошибок |
| Приложение | 2 | Оба режима работают с сохранёнными моделями, ввод проверяется, прогнозы можно скачать |
| Воспроизводимость и публикация | 2 | Есть эксперименты и свои выводы; код, данные и модели собраны по структуре проекта, README позволяет повторить запуск; доступны открытый GitHub и приложение |
| **Итого** | **10** | |

По каждой части: **2 балла** — выполнена полностью, **1 балл** — выполнена частично, **0 баллов** — отсутствует или не работает. Высокая метрика сама по себе не гарантирует полный балл: важны корректная проверка и ваше понимание результата. Обоснованный эксперимент без улучшения качества тоже засчитывается.
