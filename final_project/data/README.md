# Данные для проекта

В этой папке вас ждут два набора данных — по **7 500 объявлений о квартирах** в каждом. Их достаточно для обеих задач проекта.

Мы будем работать с одними и теми же квартирами, но зададим моделям разные вопросы:

| Файл | Целевая переменная | Что предсказываем |
|---|---|---|
| `regression.csv` | `price_rub` | Цену объявления в рублях |
| `classification.csv` | `above_reference` | Класс квартиры по готовой метке `above_reference` |


## Поля и подсказки

В папке `final_project/notebooks` есть дополнительный ноутбук `EDA_ideas.ipynb`: там вас ждут простые примеры по обработке полей для модели. Можно пользоваться только теми шагами, которые пригодятся вашему решению.

Мы с вами прошли большой путь: от анализа данных до построения моделей. В этом проекте вам пригодятся знания и навыки, полученные на курсе. Ниже перечислены поля в датасетах, их типы и идеи для обработки. Это подсказки, а не единственный способ решения: вы можете выбрать другие подходы, и новые идеи очень приветствуются! Попробуйте их и посмотрите, как они повлияют на качество модели.

| Поле | Тип и смысл | Что можно попробовать |
|---|---|---|
| `city` | Категория: город | Частоты, удаление лишних пробелов, One-Hot Encoding |
| `district` | Категория: район; много пропусков | Посчитать пропуски; заполнить отдельной категорией; сравнить модель с районом и без него. Одинаковые названия в разных городах различать сочетанием города и района |
| `street` | Категория: улица; есть пропуски и редкие значения | Проверить написания и частоты; OHE с поддержкой неизвестных значений; объединение редких категорий. Сравнить с моделью без улицы; учитывать город |
| `area` | Число: площадь, м² | Посмотреть распределение и связь с ценой; проверить масштабирование |
| `rooms` | Число: комнаты; 0 — студия | Проверить пропуски; заполнение медианой; сравнить числовую и категориальную обработку |
| `floor` | Число: этаж квартиры | Сравнить исходное поле с признаками первого/последнего этажа |
| `floors_total` | Число: этажность дома | Проверить `floor <= floors_total`; попробовать относительный этаж `floor / floors_total` |
| `house_type` | Категория: тип дома | Частоты, заполнение пропусков, OHE |
| `market_type` | Категория: первичный/вторичный рынок | Проверить значения; OHE или согласованное бинарное кодирование |
| `lift_count` | Число: количество пассажирских лифтов | Пропуски, их заполнение и индикатор отсутствия значения. Пропуск не означает отсутствие лифта |
| `listing_id` | Служебный ID объявления | Проверка и сопоставление строк; исключить из признаков |
| `group_id` | Служебная группа связанных объявлений | Контроль разбиения; исключить из признаков |
| `split` | Часть данных: `train`, `test` | Использовать для разбиения; исключить из признаков |
| `price_rub` | Общая цена квартиры в рублях: цель регрессии и входной признак классификации | Распределение, ошибки дорогих/дешёвых квартир; по желанию логарифм цели с обратным преобразованием |
| `above_reference` | Таргет для классификации | Баланс классов, precision/recall/F1; порог вероятности модели — 0.5 |

Помните, как на занятиях мы по-разному работали с числами и категориями? Здесь пригодится тот же подход. Для чисел можно попробовать заполнение пропусков и масштабирование, а для категорий — заполнение и кодирование. Выбирайте подходящий способ и сравнивайте результаты — так вы сможете понять, что помогает именно вашей модели.

## Для чего нужны служебные поля

В таблицах вы встретите три поля, которые мы добавили при подготовке данных. Они помогают организовать обучение и проверку модели:

- `listing_id` — ID объявления. По нему удобно находить повторы и сопоставлять исходную квартиру с её прогнозом.
- `group_id` — группа связанных объявлений: например, квартир одного дома или записей с одинаковыми входными признаками. Такие объявления оставляем в одной части данных, чтобы очень похожие объекты не попадали одновременно в обучение и проверку и не делали оценку качества слишком оптимистичной.
- `split` — готовое назначение строки: `train` для обучения и `test` для проверки.

Сохраните эти столбцы в датасетах, но **не включайте их в признаки модели**. Они помогают нам следить за корректностью эксперимента, а модель учится на характеристиках квартиры: площади, комнатах, городе и других выбранных вами полях.

## Разбиение без утечки

Разбиение мы уже подготовили для вас: оно записано в поле `split`. Используем только две части: на train вы будете готовить данные и обучать модель, а на test — проверять её и сравнивать учебные варианты. Для классификации оставим порог вероятности 0.5, без отдельного подбора. Пожалуйста, сохраните это разбиение: связанные объявления уже объединены в группы и не попадают одновременно в разные части.

Здесь полезно вспомнить важное правило курса: медианы для заполнения пропусков, частоты редких категорий и параметры масштабирования и кодирования определяем только по train. Затем применяем те же значения и правила к test и новым квартирам в приложении. Можно выполнять обработку простыми последовательными шагами. Запишите, что вы сделали с каждым полем, или создайте пайплайн, чтобы потом легко повторить эти действия.

Для классификации используем готовую метку `above_reference`. **Общая цена квартиры `price_rub` входит в признаки вместе с площадью и другими характеристиками, поэтому она понадобится и при работе приложения. В регрессии `price_rub` остаётся целью и не входит в признаки. В обеих задачах исключаем из входов целевую переменную и служебные столбцы.**
