# Финальный проект: две модели и приложение

Мы с вами прошли путь от знакомства с данными до построения моделей. Теперь предлагаю объединить всё, чему вы научились, в собственном приложении: научим его предсказывать цену квартиры и определять ценовой класс. В этой папке собраны данные, подсказки и заготовки, которые помогут вам начать. Места `TODO` ждут вашего кода, а модели и результаты появятся в ходе вашей работы.

Для начала загляните в [задание](TASK.md) (`final_project/TASK.md`) и [описание данных](data/README.md) (`final_project/data/README.md`). Если понадобится вспомнить знакомый приём, примеры можно найти в папках репозитория курса: `lesson_2` — анализ данных, `lesson_3` — регрессия, `lesson_4` — классификация. Пример уже развёрнутого приложения можно посмотреть в отдельном открытом репозитории `streamlit-app`. Смело пользуйтесь ими и пробуйте свои идеи.

## Что уже подготовлено для вас

```text
final_project/
├── README.md                    # с чего начать, как запустить и опубликовать проект

```

`app.py` — файл, в котором вы допишете интерфейс, загрузку моделей и получение прогнозов. Если хочется посмотреть готовый пример, загляните в отдельный открытый репозиторий `streamlit-app`: в нём находится код уже развёрнутого приложения. Его можно использовать как опору при работе над своим проектом.

Все нужные библиотеки собраны в одном `requirements.txt`: для обработки данных, обучения моделей, запуска приложения и работы с ноутбуками. В него входят `jupyterlab` — интерфейс для работы с ноутбуками, и `ipykernel` — ядро, которое выполняет в них Python-код.

По мере работы у вас появятся сами модели в папке models/ `models/price_model.joblib` и `models/class_model.joblib`. Метрики, сравнения и свои наблюдения удобно записывать прямо в ноутбуках — отдельную папку отчётов создавать не нужно. Обработку признаков можно выполнять простыми шагами. Запишите выбранные правила и значения, чтобы повторить их для новых квартир в приложении.

## 1. Начнём с окружения

Для проекта нам понадобится **Python 3.12**. Выберите удобный вам редактор: VS Code, PyCharm или другой. Откройте в нём папку `final_project`. Окружение `.venv` можно создать в настройках интерпретатора IDE и установить туда пакеты из `requirements.txt`. Если удобнее работать в терминале, воспользуйтесь командами ниже. Выполняйте их из папки `final_project`.

macOS / Linux:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Команда `python -m pip install -r requirements.txt` устанавливает все библиотеки проекта в выбранное окружение. Одинаковые версии пакетов при обучении и запуске помогут избежать проблем с загрузкой моделей.

## 2. Поработаем в ноутбуках

Если хочется начать с исследования данных и попробовать разные способы обработки полей, загляните в `EDA_ideas.ipynb` в папке `notebooks`. Это помощник: можно выбрать отдельные подсказки, дополнить их своими идеями и сохранить собственные версии датасетов.

Перед началом выберите в IDE ядро Python **из `.venv`** — тогда ноутбук увидит установленные пакеты.

1. Откройте `notebooks/01_regression.ipynb`, изучите данные и заполните `TODO` по порядку.
2. Обучите модель на train, сравните её с простым ориентиром на test и сохраните её. Отдельно сохраните нужные значения для подготовки новых данных: например, медианы и порядок столбцов после кодирования.
3. Повторите для `notebooks/02_classification.ipynb`. Обучайте на train и проверяйте на test. Для класса используйте порог вероятности 0.5.
4. Перезапустите ядро и выполните каждый завершённый ноутбук сверху вниз. Проверьте ассерты в конце.

Если вы встретили `NotImplementedError` в месте с `TODO`, всё в порядке: это приглашение дописать соответствующий шаг. В конце вас ждут ассерты — небольшие проверки прогнозов и сохранения модели. Они помогут заметить технические ошибки, но не ограничивают вас одним алгоритмом или заданным значением метрики. Эксперименты и ваши наблюдения по-прежнему остаются важной частью работы.

Разбиение уже записано в `split`, так что этот шаг за вас подготовлен. Будем использовать только две части: train для подготовки данных и обучения, test для оценки и учебного сравнения моделей. Если вы выбираете лучший вариант по test, его метрика уже не является независимой оценкой: в выводах просто укажите, что сравнивали варианты на одной тестовой части. Здесь пригодится всё, что мы обсуждали на занятиях об утечке данных.

Обратите внимание: классификатор использует общую цену `price_rub` как вход, поэтому она нужна и в загружаемом файле приложения. В регрессии это целевая переменная, и для прогноза цены вводить её не нужно.

## 3. Дадим моделям интерфейс

В `app.py` вас уже ждут выбор задачи, загрузка CSV и место для результата. Начните с функций `load_artifact`, `prepare_input` и `predict_table`: комментарии подскажут, что они принимают и возвращают. Затем помогите будущему пользователю разобраться: добавьте описание полей, пример входного CSV для скачивания и понятные сообщения об ошибках. Если хочется, можно дополнить приложение формой квартиры или загрузкой Excel. Пример для этой части есть в отдельном открытом репозитории `streamlit-app`: там находится код уже развёрнутого приложения.

Ноутбуки сохраняют словарь с ключами `model` (обученная модель), `features` (список исходных входных полей) и `preparation` (значения и правила подготовки данных). Например, в `preparation` можно хранить медианы и список столбцов после `pd.get_dummies()`. Для классификации также сохраняется `threshold = 0.5`. Правило класса: `p >= threshold`. Те же имена и правила подготовки используйте в приложении. Если меняете формат сохранения, согласованно измените загрузку в `app.py`.

```bash
python -m streamlit run app.py
```

После запуска откройте адрес, который появится в терминале. Остановить приложение можно сочетанием `Ctrl+C`. Пока функции не дописаны, вы увидите подсказку о том, какой шаг ещё предстоит реализовать.

Если что-то не получается, начните с сообщения в терминале и проверьте одну функцию за раз. Полезно взять одну и ту же квартиру и сравнить ответы приложения и ноутбука. После переобучения перезапустите приложение, чтобы оно подхватило новую модель.

## 6. Опубликуем приложение в Streamlit Community Cloud

Теперь дадим вашему приложению собственную ссылку, чтобы его могли открыть другие! Вот шаги, которые помогут это сделать:

1. Убедитесь, что завершённое решение загружено в **открытый (Public) репозиторий GitHub**. В нём должны быть `app.py`, `requirements.txt`, обе модели в `models/` и сохранённые значения, необходимые для подготовки новых данных.
2. Зайдите на [share.streamlit.io](https://share.streamlit.io/), выберите вход через GitHub и подключите свой GitHub-аккаунт. Если сервис запросит доступ к репозиториям, подтвердите подключение.
3. Нажмите **Create app** и выберите развёртывание своего приложения из GitHub.
4. Укажите **Repository** — `имя вашего репозитория`, **Branch** — `main`, **Main file path** — `app.py`. Если приложение лежит в подпапке, укажите полный путь от корня репозитория, например `final_project/app.py`.
5. В **Advanced settings** выберите **Python 3.12**, как при локальном обучении. Нажмите **Deploy**.
6. Дождитесь установки зависимостей и запуска. При ошибке откройте логи: проверьте пути к моделям, необходимые файлы и версии пакетов.
7. Откройте полученную ссылку вида `https://....streamlit.app`, проверьте оба режима и скачивание прогнозов. Добавьте ссылку на приложение и на репозиторий в README своей работы и отправьте их преподавателю.

После обновления файлов в GitHub сервис применяет изменения к приложению. Если потребуется, обновите файлы моделей в GitHub. Если меняли код, загрузите и его. Streamlit автоматически обновит уже опубликованное приложение.
